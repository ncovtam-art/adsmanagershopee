# Kiến trúc

Ứng dụng sử dụng Next.js App Router cho React UI và API Route Handlers. Backend modular nằm tại `src/server`, tách Authentication, Team, Settings, HTTP security/error và Database. Service nhận `AppDatabase` qua constructor, cho phép integration tests dùng Database riêng; không phụ thuộc Next.js.

Luồng mutation: Origin validation → session lookup → permission backend → JSON mặc định giới hạn 16 KiB (Publisher preview/confirm 64 KiB) → Zod validation → service transaction → response có `Cache-Control: no-store`. API dùng `{data: ...}` khi thành công, `{error: {code, message}}` khi thất bại. Server page tự đọc lại session trước khi trả dữ liệu; không chỉ dựa vào layout hoặc ẩn nút.

Authentication dùng scrypt N=32768/r=8/p=1, salt ngẫu nhiên cho từng mật khẩu; session token ngẫu nhiên 256 bit, chỉ hash SHA-256 được lưu Database. Cookie HttpOnly/SameSite=Lax, hết hạn sau 12 giờ; Secure bắt buộc cho production HTTPS. Logout xóa session; khóa tài khoản xóa toàn bộ session và check trạng thái trên mỗi request. Giới hạn login theo email bằng Database/advisory lock, 5 lần sai trong 15 phút; lỗi không tiết lộ email tồn tại. Không tin `Host`/forwarded headers để xác định Origin.

RBAC cơ bản: OWNER/ADMIN quản lý nhân viên và cấu hình; MANAGER/MEDIA_BUYER có quyền tài chính; UPLOADER/VIEWER đọc workspace nhưng không xem tài chính. ADMIN không được tạo/khóa ADMIN khác; chỉ OWNER làm được. Không có API tạo OWNER. Giai đoạn 2 thêm resource grants kiểm tra list/detail/mutation từng Page/TKQC. OWNER/ADMIN quản lý Meta; MANAGER/MEDIA_BUYER viết Donor trong account scope. Chưa có finance scope chi tiết/module grant tùy biến cho các module chưa triển khai.

UI dùng CSS design tokens, base components, sáu menu cố định, tiếng Việt, responsive/reduced motion, Empty State, loading, error boundary và confirmation. Không tải font hoặc gọi API bên ngoài để hiển thị. Ô tìm kiếm hiện tìm mục điều hướng; tìm kiếm nghiệp vụ chưa triển khai.

PostgreSQL + Drizzle thay cho Prisma được đề xuất vì tải engine/checksum Prisma bị proxy chặn trong môi trường này. Đây là quyết định cho repository ban đầu trống. Drizzle tạo SQL migration; migrator kiểm hash migration đã áp dụng và dùng advisory lock chống chạy trùng. Không reset Database khi migration lỗi.

Đã thêm MetaGateway + provider interface LIVE/MOCK, official OAuth state, token AES-GCM, cache token-scoped, paging cursor, usage/cooldown/retry. Import CSV/XLSX chạy server bằng parser Node (`read-excel-file` external package trong Next build để không bundle nhánh AWS S3 tùy chọn không dùng). Donor đọc và xác minh cấu trúc trước preview; save đọc lại, so fingerprint và transaction append version. Mock không tự bật khi thiếu credentials; namespace/nhãn tách LIVE. UI không nhận token.

Giai đoạn 6 thêm Redis/BullMQ cho publish/comment jobs, idempotency và recovery khi mutation Meta có kết quả UNKNOWN. Publish endpoints yêu cầu Origin, RBAC và confirm; Giai đoạn 7 thêm Ads create endpoints PAUSED. Tiền báo cáo Decimal/tổng BigInt, ngân sách Meta string integer, tất cả Meta IDs string.

Production hardening (Giai đoạn 10) còn cần HTTPS deployment, secret storage, CSP nonce chặt hơn, password recovery/MFA, giới hạn login theo nguồn truy cập đáng tin cậy, backup/restore, monitoring và kiểm tra tải. Phiên bản này là nền tảng phát triển, chưa phải nghiệm thu production.

Giai đoạn 4 thêm Shopee tracking/CSV/reconciliation services, không gọi Shopee API. Source/affiliate-account namespace và immutable mapping/link versions tách khỏi dữ liệu LIVE/Mock. Upload multipart được giới hạn trước parse; CSV arrays tránh prototype columns. Preview không ghi ledger; commit serialized bằng advisory lock, fingerprints và row identity/revision; history append-only. UI financial source/filter có response context guard chống hiển thị nguồn cũ trong lúc fetch. Không reuse link/shared history để tự chia hoa hồng về Ads.

Giai đoạn 5 thêm AnalyticsService/Gateway Insights + pure Decimal/date/CSV engine; dashboard API chỉ đọc Database, Meta sync là mutation có Origin/RBAC. Facts chọn một nguồn theo account/day, reporting level Ad và daily timezone của account; aggregate theo hierarchy không cộng khác cấp. Attribution chỉ dùng mapping/link riêng đã xác nhận, status ledger mới nhất và order date; guard thay reporting dimension/Unmatched/currency/shared/missing/review/freshness. Worker riêng dùng PostgreSQL schedule/claim; chưa cần Redis cho job đọc định kỳ hiện tại. Frontend response-context guard giữ source/account/filter khớp; user views browser-scoped, raw imports không gửi client. Xem ADS_ANALYTICS.md.

Publisher có validation/storage/provider/service/engine/queue riêng. Raw upload stream vào file private, SHA-256 và ffprobe local, không dùng URL tải file từ người dùng. Confirm transaction đóng băng nội dung/link/policy và append-only history. PostgreSQL outbox đẩy vào hai BullMQ queues video_publish/post_comment; lease theo Page, heartbeat và phase persist trước mutation. Gateway writes không retry kết quả mơ hồ; UNKNOWN chỉ phục hồi bằng read/verified adoption, Post ID thực trước comment, parent unique chống comment lặp. Redis mất dữ liệu không thay PostgreSQL job state. Worker và web dùng media cùng filesystem; nhiều máy/object storage thuộc hardening.

AdsService/AdsProvider dùng normalized allowlist, connection/page/account/source checks và official gateway writes không retry mơ hồ. PostgreSQL single-request workflow worker riêng, row lease/heartbeat, phase trước mutation/ID trước read verification; source IDs không vào payload. Readback account/name marker/config/parents/PAUSED trước success; UNKNOWN adoption có lý do/audit. New Creative link snapshot frozen và per-Ad tracking chỉ bind IDs sau verify; Existing Post giữ SHARED/SubID. Bulk/Cloning và distributed limits thuộc giai đoạn sau.

BulkAdsService tạo preview thuần/read-only, planner partition theo Page/account/source, fingerprints/preset/clone membership, totals BigInt theo parent và currency/budgetkind. Confirm transaction/advisory lock ghi graph + snapshots, ref chỉ trỏ parent đã xác minh hoặc leader trước đó. AdsService tiếp tục engine cũ với material owner/name-marker, batch boundary và WAITING. BullMQ stage8 outbox id/generation, PG authoritative state; namespace test riêng. Preparation theo row key transactional/idempotent, URL/SubID riêng reuse TrackingService. No blind UNKNOWN retry.
